# CB 后台管理系统

用于管理「CB」的后台系统。

- 后端：Python + FastAPI + sqlite3（Python 标准库 `sqlite3`，无 ORM）
- 前端：Vue3 + Vite + Element Plus
- 默认账号：`admin` / `admin123`

## 目录结构

```
cbsystem/
├── backend/
│   ├── main.py            # FastAPI 入口
│   ├── database.py        # sqlite3 连接、建表、站点设置读写
│   ├── image_store.py     # 图片保存/访问/目录迁移/无引用清理
│   ├── backup.py          # 数据备份（导出 zip）与恢复（上传 zip）
│   ├── oplog.py           # 操作日志：写入与查询
│   ├── security.py        # 密码加密 / JWT 签发校验 / 登录依赖
│   ├── routers/
│   │   ├── auth.py        # 登录接口
│   │   ├── groups.py      # 分组管理接口
│   │   ├── cb.py          # CB 管理接口 + 图片上传
│   │   ├── favorites.py   # 收藏记录接口 + 收藏/取消收藏
│   │   ├── sites.py       # 网站管理接口（与 CB 相关的网址清单）
│   │   ├── logs.py        # 日志记录接口（查询 / 批量删除 / 清空）
│   │   ├── settings.py    # 网站设置：站点名称、图片目录、清理图片、备份恢复
│   │   └── media.py       # /uploads/xxx 图片访问
│   ├── data/app.db        # SQLite 数据库（首次启动自动生成）
│   └── uploads/           # 默认图片目录（可在「网站设置」里改到任意文件夹）
└── frontend/
    ├── src/
    │   ├── api/index.js          # axios 封装（自动带 token、统一错误提示）
    │   ├── router/               # 路由 + 登录守卫
    │   ├── store/settings.js     # 站点名称（登录页/布局/浏览器标题共用）
    │   ├── components/CbTable.vue  # CB管理 / 收藏记录 共用的表格组件
    │   └── views/                # Login / Layout / CbManage / FavoriteManage / GroupManage / SiteManage / LogManage / SettingManage
    └── vite.config.js     # 开发代理：/api、/uploads -> 127.0.0.1:8024
```

## 启动方式

### 1. 启动后端（端口 8024）

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8024
```

接口文档：http://127.0.0.1:8024/docs

首次启动会自动完成：

- 创建 `data/app.db` 及 `users` / `groups` / `cb` / `favorites` / `sites` / `app_settings` / `operation_logs` 七张表
- 若 `cb` / `favorites` 是旧版本建的表，自动补上 `event_date`（时间）、`aliases`（别名）两个字段，并用创建日期回填「时间」
- 写入管理员账号 `admin` / `admin123`
- 写入默认站点名称与默认分组：`WantA`、`Want4`、`Want`、`UP`、`Color`、`Perfeat`、`Hard`、`CN`、`Sweet`、`Day`、`Desk`

> 说明：需求中的默认分组里 `Color` 出现了两次，已自动去重。

### 2. 启动前端（端口 5173）

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开 http://127.0.0.1:5173 ，使用 `admin` / `admin123` 登录。

（也可以直接双击根目录下的 `start-backend.bat` 和 `start-frontend.bat`。）

## 功能说明

### 登录

- JWT 鉴权，token 有效期 7 天，存于 `localStorage`，请求头自动携带 `Authorization: Bearer <token>`
- 未登录访问任意页面会被路由守卫重定向到登录页；token 失效时自动跳回登录页

### 菜单一：CB管理

| 列 | 说明 |
| --- | --- |
| CB名称 | 列表内直接编辑 |
| 时间 | 日期，默认为创建当天，可在列表内直接改 |
| 别名 | 一个 CB 可以有多个别名，列表内以标签展示、编辑时输入后回车添加 |
| 分组 | 下拉选择，选项来自「分组管理」 |
| 图片 | 统一 64×64 缩略图，点击可放大预览，最多 3 张 |
| 备注 | 列表内直接编辑 |
| 操作 | 编辑 / 收藏（取消收藏）/ 删除 |

- **新增**：点击「新增 CB」，列表首行出现可编辑空行，填好后保存
- **修改**：点击行内「编辑」，该行各部分直接变为输入框，改完点「保存」；同一时间只能编辑一行
- **时间**：新建时默认填当天，可改成任意日期；编辑时清空则保持原值不变
- **别名**：最多 20 个，每个最长 100 字，自动去空去重。**搜索 CB 名称时别名同样参与匹配**，因此同一个 CB 的多个叫法都能搜到
- **图片**：编辑状态下点击虚框「上传」选择本地图片，或直接 **Ctrl + V 粘贴** 图片到表格（也支持粘贴图片 URL），缩略图右上角 ✕ 可移除
- **收藏**：点击「收藏」会在「收藏记录」中新增一条记录（连同「时间」「别名」一起复制过去），按钮变为「取消收藏」；再次点击记录即消失
- **删除**：二次确认后删除
- **分页**：支持每页 10/20/50/100 条，支持按「名称 / 别名」关键词、按分组筛选

### 菜单二：收藏记录

功能与「CB管理」一致（列表内编辑、缩略图最多 3 张、支持粘贴与上传、分页/筛选），数据来自 CB 页面点击「收藏」时复制的一份快照。

| 列 | 说明 |
| --- | --- |
| CB名称 | 列表内直接编辑 |
| 时间 | 日期，从来源 CB 复制过来，可单独修改 |
| 别名 | 从来源 CB 复制过来，可单独增删；同样参与搜索 |
| 分组 | 下拉选择，选项来自「分组管理」 |
| 图片 | 统一 64×64 缩略图，点击可放大预览，最多 3 张 |
| 备注 | 列表内直接编辑 |
| 操作 | 编辑 / 删除 |

说明：

- 一个 CB 最多对应一条收藏记录，重复点击只会在「收藏」与「取消收藏」之间切换
- 收藏记录是独立数据，在收藏页修改不会同步回 CB 管理；反之亦然
- 删除 CB 不会删除对应的收藏记录（该记录的来源标记会置空）

### 菜单三：分组管理

| 列 | 说明 |
| --- | --- |
| 分组名称 | 唯一，重复会提示「分组名称已存在」 |
| 分组排序 | 数字，越小越靠前，列表按此排序 |
| 操作 | 编辑 / 删除 |

删除分组后，原来属于该分组的 CB 会变为「未分组」（不会级联删除 CB）。

### 菜单四：网站管理

存放与 CB 相关的网址清单。

| 列 | 说明 |
| --- | --- |
| 网址 | 必填，列表里是超链接，**新窗口打开** |
| 创建日期 | 默认当天，可在列表内直接改 |
| 收藏内链 | 选填，同样是超链接、新窗口打开 |
| 作用级别 | 1 - 5，列表内下拉选择 |
| 支持下载 | 是 / 否 |
| 状态 | 正常 / 作废 |
| 操作 | 编辑 / 作废（恢复）/ 删除 |

- **新增**：点击「新增网站」，列表首行出现可编辑空行，填好后保存
- **修改**：点击行内「编辑」，改完点「保存」；同一时间只能编辑一行
- **作废 / 恢复**：同一颗按钮来回切换。作废只是把状态改成「作废」，记录还在
- **删除**：二次确认后**硬删除**，不可恢复——只想停用请改用「作废」
- **查询**：支持按「网址 / 收藏内链」关键词搜索，并按状态（全部 / 正常 / 作废）筛选；分页每页 10/20/50/100 条

网址的规整规则：

- 不写协议头会自动补上 `https://`，`example.com` 存成 `https://example.com`
- 只放行 `http` / `https`。`javascript:`、`mailto:`、`data:`、`ftp://` 一律拒绝，
  避免伪协议被前端渲染成可点击的链接
- `localhost:8024/cb` 这类「域名:端口/路径」的写法能正确识别（冒号后是端口号，不算伪协议）
- 网址在表内唯一，重复会提示「该网址已存在」

### 菜单五：日志记录

记录系统里的每一次写操作，按时间倒序排列（最新的在最上面），显示成 `时间 + 操作 — 对象`：

```
2026年9月16日 16:35:09    备份数据 — cbsystem-backup-20260916-163509.zip
2026年9月16日 16:34:09    新增分组 — WantA
2026年9月16日 16:33:09    删除CB — XXXX
2026年9月16日 16:32:09    新增CB — XXXX
2026年9月16日 16:31:09    收藏CB — XXXX
```

- 支持关键词搜索（同时匹配「操作」和「对象」）、分页（每页 20/50/100/200 条）
- **多选删除**：勾选若干行后点「批量删除」，按钮上会显示已选条数。勾选可以跨页累积，
  但改动查询条件、重置或删完之后会自动清空，避免误删上一批筛选结果
- 「清空日志」二次确认后删除全部日志。批量删除与清空本身都会补记一条，所以删完列表里还会留下记录

被记录的操作：

| 动作 | 对象 |
| --- | --- |
| 登录系统 | 用户名 |
| 新增 / 修改 / 删除 分组 | 分组名称 |
| 新增 / 修改 / 删除 CB | CB 名称 |
| 收藏CB / 取消收藏 | CB 名称 |
| 新增 / 修改 / 删除 收藏 | 名称 |
| 新增 / 修改 / 删除 网站 | 网址（去掉 `https://` 前缀） |
| 作废网站 / 恢复网站 | 网址（去掉 `https://` 前缀） |
| 修改网站设置 | 站点名称（改了图片目录时附上新目录） |
| 清理未引用图片 | 清理张数 |
| 备份数据 | 数据包文件名 |
| 恢复备份 | 数据包文件名 + 恢复条数 |
| 清空日志 | 清空条数 |
| 删除日志 | 批量删除的条数 |

说明：

- 只记录**写操作**。查询、筛选、翻页这类读取动作不进日志，否则日志会被刷爆
- 日志与业务数据写在同一个事务里；万一日志写入失败也不会影响业务操作本身
- 恢复备份**不会**清空或回滚日志（日志属于审计数据），恢复动作本身会另记一条
- 数据包**不含**日志，因此在别的机器上恢复后，日志是从零开始的

### 菜单六：网站设置

| 项 | 说明 |
| --- | --- |
| 站点名称 | 最多 50 字，保存后立即作用于浏览器标签、登录页标题和侧边栏顶部 |
| 图片存放位置 | 点「浏览...」弹出系统文件夹选择框，在磁盘上指定目录；也可以手动填写路径；留空 / 点「恢复默认目录」则回到 `backend/uploads` |
| 清理未引用图片 | 手动清理磁盘上已不被任何 CB / 收藏记录引用的图片 |
| 备份数据 | 导出数据包（`.zip`），浏览器直接下载 |
| 恢复备份 | 上传数据包，整体覆盖当前数据 |

图片清理规则：

- 删除 CB 时，如果该 CB 还被「收藏记录」引用着（收藏记录与 CB 共用同一批图片路径），**图片会保留**
- 只有当这个 CB 在「CB管理」和「收藏记录」里**都**被删除后，图片才会真正从磁盘移除
- 在列表里编辑移除某张缩略图并保存，同样会触发检查，没有其他记录引用就直接删除
- 更换图片目录时，已有图片会自动**移动**到新目录，历史缩略图不会失效

#### 备份数据

导出的数据包是一个 `.zip`，结构如下：

```
cbsystem-backup-20260916-103000.zip
├── backup.json      分组、CB、收藏记录（含图片路径）、网站、站点名称
└── images/          上述记录实际引用到的图片文件
```

- 文件名形如 `cbsystem-backup-<年月日>-<时分秒>.zip`
- 只打包**真正还被引用**的图片，磁盘上的孤儿图片不会进包
- CB / 收藏的每条记录都带上「时间」（`event_date`）和「别名」（`aliases`）
- 网站清单（`sites`）也在包里，级别 / 是否下载 / 状态一并保留
- **不含 `users` 表**，因此数据包里没有账号密码，恢复后用当前账号登录即可
- **不含 `operation_logs`**：日志是审计数据，恢复历史数据不会把它一起回滚
- **不含图片目录**：目录属于目标机器的本地配置，包内图片一律还原到目标机器「网站设置」里当前配置的目录
- 恢复**旧版数据包**同样可以：没有 `event_date` 就用创建日期补上，没有 `aliases` 就是空别名，
  没有 `sites` 则网站列表会被清空（恢复是整体覆盖）
- 数据包里被手工改脏的网站记录会被**静默修正**而不是让整次恢复失败：
  级别越界收敛成 1、状态乱填收敛成「正常」、缺 `url` 的记录直接丢弃

#### 恢复备份

- 选择 `.zip` 后二次确认，随后**整体覆盖**当前的分组、CB、收藏记录、网站，并把图片释放到当前图片目录
- 站点名称也会一并还原成备份时的值
- 整个过程在一个事务里完成，中途出错会自动回滚，不会留下半套数据
- 恢复后会自动清理掉已被替换的旧图片（仍被引用的不动）
- 非法输入会被挡下并给出提示：非 zip 文件、缺少 `backup.json`、版本不匹配、空文件、超过 200MB
- 数据包内的图片条目只取文件名，`../`、绝对路径等一律丢弃，不会写到图片目录之外

| DELETE | `/api/sites/{id}` | 删除网站 |
| GET | `/api/logs?page=&page_size=&keyword=` | 操作日志分页列表（按时间倒序） |

| POST | `/api/settings/pick-folder` | 弹出系统文件夹选择框，返回选中的绝对路径 |
| POST | `/api/settings/cleanup-images` | 清理未被任何记录引用的图片 |

| POST | `/api/settings/restore` | 上传数据包恢复（multipart，字段名 `file`） |
| GET | `/api/settings/public` | 仅返回站点名称（**免登录**，登录页要用） |

> `/api/cb` 列表返回的每条数据会带有 `is_favorite` 字段，用于渲染收藏按钮的状态。
> 图片上传统一走 `/api/cb/upload`，两个页面共用。
> `/api/cb`、`/api/favorites` 的 `keyword` 同时匹配名称和别名；返回的每条数据都带 `event_date`（`YYYY-MM-DD`）和 `aliases`（字符串数组）。

## 备注

- 图片目录默认是 `backend/uploads/`，可在「网站设置」里改到磁盘上任意文件夹；数据库中仅存相对路径（如 `/uploads/xxx.png`）。
- 由于目录可以随时改，图片访问没有用 `StaticFiles` 挂载固定目录，而是由 `routers/media.py` 每次请求实时解析当前目录。
- 前端开发环境通过 Vite 代理把 `/api`、`/uploads` 转发到后端，因此不存在跨域问题。
- 生产部署时，执行 `npm run build` 后把 `frontend/dist` 交给 Nginx 等统一托管，并把 `/api`、`/uploads` 反向代理到后端。
- `security.py` 中的 `SECRET_KEY` 建议上线前替换。
- 「浏览...」按钮调用的是运行后端的这台机器上的系统对话框（`tkinter`，Python 自带）。若运行环境无法弹窗（例如无图形界面），接口会返回提示，改为手动填写路径即可。
- 备份 / 恢复用的是 Python 内置的 `zipfile` + `json`，与图片、收藏、网站设置一样没有引入任何第三方依赖，`requirements.txt` 无需变更。
- 数据包版本号定义在 `backup.py` 的 `BACKUP_VERSION`。日后若表结构有变，改动这里即可让旧数据包在恢复时被明确拒掉，而不是写入半套脏数据。
- 新增「网站管理」时给数据包加了 `sites` 键，但**没有**升版本号：旧包取不到 `sites` 就是空列表，属于可预期的降级，不需要把旧包一刀切拒掉。
- `event_date` / `aliases` 两个字段是给「CB」「收藏记录」和「网站」共用的同一套规整逻辑（`routers/cb.py` 里的 `clean_date` / `clean_aliases`），网站那边直接复用，没有另写一份。
